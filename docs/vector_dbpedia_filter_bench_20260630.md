# dbpedia фильтр/тенант бенч — dim-aware + residual-aware brute (commit 3fbfd78)

Полные результаты прогона `TestDBpedia_FilterTenant` (30.06.2026), на которых принят
коммит `3fbfd78` (dim-aware brute-порог #1 + residual-aware brute #2). Сохранено для
истории — сырой вывод теста транзиентен.

## Сетап

- Данные: **dbpedia-openai 100k×1536**, ada-002, **cosine** (normalized dot), нормированы.
- N=100000, запросов q=200, **ef=128, K=10, потоков W=12**, один сегмент (segs=1).
- `PartitionAttr=tenant`; blocks (размер тенанта) = [1000, 16000, 30000, 40000].
- `base` = SearchFiltered (строковый предикат); `filt` = SearchFilter (колонки) / SearchTenant (каталог).
- Метрика speedup = filt_QPS / base_QPS. recall@10 vs точный.
- ⚠ Колонка `route` в таблице — СТАТИЧЕСКАя метка по сырому порогу 16384; фактический
  внутренний маршрут после фикса #1 dim-aware (на 1536d порог ~1365), поэтому,
  например, single B16k помечен `brute`, но реально идёт `graph` (отсюда скачок QPS).

## Заметки

- **B40k-multi = 274 QPS — это ПОЛ подхода brute/graph**, не стена алгоритма: стоимость
  задаёт число дистанций (5000 совпавших × 1536d), а не маршрут. Порогом не сдвигается
  (measured: brute-по-блоку и graph оба ≈274). Сломать пол может только filter-aware
  ANN (меньше 5000 дистанций) — см. план в memory `vector-large-tenant-filter-plan-20260630`.
- **Опровергнута оценка** «фикс #2 → 9× / ~2000 QPS» (memory `vector-dbpedia-filter-qps-20260629`):
  brute линеен по числу совпавших, реальный потолок B40k ≈274. Предсказание по
  остальным ячейкам (480/679/366) совпало с прогоном 1:1.
- **Промежуточный (отладочный) прогон** с наивным фиксом #2 (порог привязан к dim-aware
  блок-порогу ~1365) дал SQ8 multi B16k=152 (регрессия), B30k=206, B40k=246 — этот
  вариант отброшен, в коммит вошёл исправленный (ef×32 budget + selectivity-гард).
